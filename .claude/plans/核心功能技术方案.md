## 1. 权限系统设计

### 功能概述
实现多租户环境下的细粒度权限控制，支持模型级、对象级、字段级和数据范围权限，确保数据安全性和业务灵活性。

### 业务场景与需求
- 销售人员只能查看和操作自己负责的客户和商机
- 销售经理可以查看本部门所有数据，进行团队管理
- 管理员可以查看全公司数据
- 敏感字段（佣金比例、利润率、手机号）需要字段级权限控制
- 公海池领取时需要隐藏联系方式，防止恶意刺探
- 导出操作需要独立权限控制并记录审计日志

### 技术方案

**架构选型**:
- Django 内置权限（模型级 CRUD）
- django-guardian（对象级权限）
- 自定义 Policy 层（复杂业务规则）

```python
class DataScope(Enum):
    SELF = 'self'  # 本人数据
    DEPARTMENT = 'department'  # 本部门数据
    DEPARTMENT_AND_SUB = 'department_and_sub'  # 本部门及下级
    COMPANY = 'company'  # 全公司数据

class DataScopeQuerySet(models.QuerySet):
    def filter_by_scope(self, user, scope=None):
        if scope == DataScope.SELF:
            return self.filter(owner=user)
        elif scope == DataScope.DEPARTMENT:
            return self.filter(owner__department_id=user.department_id)
        elif scope == DataScope.DEPARTMENT_AND_SUB:
            department_ids = self._get_sub_department_ids(user.department_id)
            return self.filter(owner__department_id__in=department_ids)
        return self.none()
```

**字段级权限 Serializer 实现**:
```python
class DynamicFieldsSerializer(serializers.ModelSerializer):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        request = kwargs.get('context', {}).get('request')
        if request:
            self._filter_fields_by_permission(request.user)
    
    def _filter_fields_by_permission(self, user):
        for field_name in list(self.fields.keys()):
            if not user.has_perm(f'view_{self.Meta.model.__name__.lower()}_{field_name}'):
                self.fields.pop(field_name, None)

class CustomerSerializer(DynamicFieldsSerializer):
    class Meta:
        model = Customer
        fields = ['id', 'name', 'phone', 'email', ...]
```

- 敏感字段脱敏显示需要前端配合，避免数据泄露
- 跨部门临时授权需要完善的审批和回收机制

### 实施建议
- **P0**: Django 内置权限 + 数据范围过滤 + 审计日志（create/update/delete）

```python
from redis import Redis
import time

# 全局限流连接复用，避免重复创建Redis连接
redis_client = Redis(host='localhost', port=6379, db=0)

class FeishuRateLimiter:
    """飞书API全局限流器，防止触发频率限制（50次/秒）"""
    def __init__(self, redis_client, max_requests=50, window=1):
        self.redis = redis_client
        self.max_requests = max_requests
        self.window = window
    
    def acquire(self):
        """获取API调用许可，超限时自动等待"""
        key = f"feishu:rate_limit:{time.strftime('%Y-%m-%d-%H')}"
        current = self.redis.incr(key)
        if current == 1:
            self.redis.expire(key, self.window)
        if current > self.max_requests:
            time.sleep(self.window)
            return self.acquire()
        return True

# 在Celery任务中使用限流器
rate_limiter = FeishuRateLimiter(redis_client)

@shared_task
def sync_feishu_data(tenant_id):
    """飞书同步任务，集成限流器防止API限流失败"""
    rate_limiter.acquire()  # 获取API调用许可，超限自动等待
    # 调用飞书API
    response = feishu_api.get_departments()
```

## 3. LTV 计算引擎

### 功能概述
实现客户生命周期价值（LTV）计算，采用 4 层模型架构，支持事件驱动增量计算、工商数据自动填充、算法版本管理和 A/B 测试。

### 业务场景与需求
- 商机赢单后需立即重算 LTV
- 客户档案更新后需增量重算
- 冷启动客户使用启发式评分（行业基准 + 首次订单金额）
- 高价值客户流失风险预警
- 销售资源向高 LTV 客户倾斜

### 技术方案

**4 层模型架构**:
1. Customer（基础信息 + LTV 缓存）
2. CustomerLTVProfile（LTV 输入特征）
3. CustomerLTV（LTV 结果 + 历史追踪，双轨输出：score + amount）
4. LTVHistory（LTV 历史记录）

**计算架构**: 事件驱动增量计算 + 定期全量重算（每周/每月）

**依赖变更检测**: 对 Customer/CustomerLTVProfile/Opportunity/Order 关键字段变更追踪

**工商数据集成**: 企查查主 + 天眼查备用，Redis 缓存 7 天，失败重试 + 降级

**算法迭代**: LTVAlgorithmVersion + A/B 测试框架

### 关键技术点
- 批处理策略：batch_size=100，max_concurrent_tasks=5，目标吞吐量 >1000 客户/分钟
- 性能目标：单次计算 <100ms（DB 40ms + 计算 40ms + 写入 20ms）
- 计算公式：LTV = (显性价值 × 0.4) + (隐性价值 × 0.4) + (增长价值 × 0.2)
- 双轨输出：
  - `ltv_score`（0-100）：基于RFM（Recency, Frequency, Monetary）模型的评分
  - `ltv_amount`：客户历史总交易金额
- 数据完整性检查：数据完整度 < 40% 标记为 "数据不足"
- A/B 测试：按客户 ID hash 分流，记录算法版本到 LTVHistory

**LTV 计算公式**:
```
显性价值 = min(revenue_2024_wan / max_revenue_wan * 40, 40)
隐性价值 = (industry_position_score + known_history_performance + past_three_years_performance) / 3
增长价值 = min(future_three_years_opportunity / max_opportunity * 20, 20)

ltv_score = 显性价值 + 隐性价值 + 增长价值 (0-100)
ltv_amount = sum(historical_revenue + current_pipeline_value + predicted_revenue)
```

### 风险与注意事项
- LTV 计算可能占用大量资源，需要控制并发数
- 工商数据 API 可能不稳定，需要降级策略
- 算法升级需要历史数据回溯，计算成本高
- 冷启动启发式评分可能偏差大，需快速迭代

### 实施建议
- **P0**: 基础 LTV 计算算法（V1.0）+ 依赖追踪 + 事件触发
- **P1**: 批量计算优化 + 工商数据集成 + 基础监控
- **P2**: 多版本算法框架 + A/B 测试系统 + 性能基线测试

## 4. 多租户隔离中间件

### 功能概述
实现多租户数据隔离，通过 Django 中间件自动注入租户 ID，配合 TenantAwareModel 模型基类和 PostgreSQL RLS 作为安全兜底。

### 业务场景与需求
- 不同企业的数据完全隔离
- 用户登录后只能看到本企业的数据
- 跨租户访问尝试需记录安全审计日志
- 需支持超级管理员跨租户查询（显式 context + 只读模式）

### 技术方案

**租户隔离强制保障（修复P0问题21）**:
- 禁止依赖开发者手动添加 tenant_id 过滤
- 必须使用强制过滤的 Manager（TenantAwareManager）
- 数据库层面使用 PostgreSQL RLS 作为安全兜底

**中间件设计**:
```python
from .context import set_current_tenant_id, get_current_tenant_id

class TenantMiddleware(MiddlewareMixin):
    def process_request(self, request):
        tenant_id = self._extract_tenant_from_request(request)
        request.tenant_id = tenant_id
        set_current_tenant_id(tenant_id)  # 与get_current_tenant_id配套

        # 设置 PostgreSQL RLS 变量（数据库层隔离兜底方案）
        with connection.cursor() as cursor:
            cursor.execute("SET app.current_tenant_id = %s", [tenant_id])
```

**模型基类**:
```python
class TenantAwareModel(models.Model):
    tenant = ForeignKey('Account', on_delete=CASCADE)

    class Meta:
        abstract = True
        indexes = [
            Index(fields=['tenant']),
        ]

    def save(self, *args, **kwargs):
        if not self.tenant_id:
            current_tenant_id = get_current_tenant_id()  # 与set_current_tenant_id配套
            if current_tenant_id:
                self.tenant_id = current_tenant_id
        super().save(*args, **kwargs)

# 禁止依赖开发者手动添加 tenant_id 过滤，必须使用 TenantAwareManager 进行强制过滤
class TenantAwareManager(models.Manager):
    def get_queryset(self):
        queryset = super().get_queryset()
        tenant_id = get_current_tenant_id()  # 使用get_current_tenant_id与set_current_tenant_id保持一致
        if tenant_id:
            return queryset.filter(tenant_id=tenant_id)
        return queryset


class TenantAwareQuerySet(models.QuerySet):
    def with_tenant(self, tenant_id):
        return self.filter(tenant_id=tenant_id)
```

```python
from django_fsm import FSMIntegerField, transition

class ApprovalInstance(models.Model):
    """审批实例"""
    status = FSMIntegerField(
        choices=[
            (0, 'draft'),
            (1, 'submitted'),
            (2, 'reviewing'),
            (3, 'approved'),
            (4, 'rejected'),
            (5, 'cancelled'),
        ],
        default=0

    @transition(field=status, source=0, target=1)
    def submit(self, user):
        self.submitted_by = user
        self.submitted_at = timezone.now()
    
    @transition(field=status, source=1, target=2)
    def start_review(self):
        pass
    
    @transition(field=status, source=2, target=3)
    def approve(self, user):
        self.approved_by = user
        self.approved_at = timezone.now()
    
    @transition(field=status, source=2, target=4)
    def reject(self, user, reason):
        self.rejected_by = user
        self.rejected_at = timezone.now()
        self.rejection_reason = reason
    
    @transition(field=status, source=[0, 1, 2], target=5)

        self.cancelled_by = user
```

```python
@shared_task
def find_duplicate_candidates_async(tenant_id, search_name, similarity_threshold=0.7):
    """异步计算客户相似度，避免实时查询超时（修复P1问题18）"""

        tenant_id=tenant_id,
```

- 大批量查重可能影响系统性能
- 相似度阈值需要根据实际业务调整
- 查重结果需要前端配合展示

### 实施建议
- **P0**: 基础查重算法（编辑距离 + 拼音）
- **P1**: 多字段综合查重 + UI 实现
- **P2**: 性能优化 + 高级算法
