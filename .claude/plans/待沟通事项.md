### 🔴 高优先级（P0-P1）- 必须深入研究

#### 1. 权限系统设计 ⭐⭐⭐
**复杂度**: High | **优先级**: High

**技术挑战**:
- RBAC + 数据权限（owner/department/tenant）
- 多系统协作的授权方案
- 审计日志的完整性

**业务需求**:
- 字段级权限控制（营收数据、佣金比例）
- 公海池数据隔离（防止刺探情报）
- 敏感字段脱敏显示

**需要研究**:
- Django 权限框架选型（django-guardian / django-rules）
- 字段级权限实现方案
- 数据范围权限（本人/本部门/全公司）
- 审计日志设计（操作记录、数据变更追踪）
- 前端权限控制（按钮/字段显示隐藏）

---

#### 2. 飞书集成深度设计 ⭐⭐⭐
**复杂度**: High | **优先级**: High

**技术挑战**:
- 组织架构增量同步策略（分页、游标、变更事件）
- Token 刷新与限流处理（200 req/min）
- Webhook 签名验证、幂等、重试
- 审批流程回写一致性

**需要研究**:
1. 飞书 OpenAPI 增量同步方案
   - 使用 Webhook 还是定时轮询？
   - 如何处理组织架构的增量变更？
   - 分页策略和游标管理

2. Token 管理
   - Redis 缓存策略
   - 提前刷新机制（过期前5分钟）
   - 多租户 Token 隔离

3. Webhook 处理
   - 签名验证流程
   - 幂等性保证（去重表）
   - 重试策略（指数退避）
   - 失败告警

4. 审批集成
   - 审批流程引擎选型（飞书审批 vs 自建）
   - 状态回写机制
   - 异常补偿流程

---

#### 3. LTV 计算引擎 ⭐⭐⭐
**复杂度**: High | **优先级**: High

**技术挑战**:
- 双轨制 LTV 与多表关联（Profile/History）
- 批处理策略与增量计算
- 定时任务调度频率与性能控制

**业务需求**:
- 工商数据自动填充（企查查/天眼查 API）
- 数据完整性检查
- 冷启动启发式评分

**需要研究**:
1. 计算架构
   - 全量计算 vs 增量计算
   - Celery 定时任务调度（每日/每周）
   - 批处理性能优化（分批、并行）

2. 数据源集成
   - 企查查/天眼查 API 对接
   - 数据映射和清洗逻辑
   - 自动更新策略（定期刷新）

3. 算法迭代
   - 多版本 LTV 算法并存（A/B 测试）
   - 权重调整机制
   - 历史数据回溯计算

4. 性能基线
   - 单次计算耗时目标（<100ms/客户）
   - 批量计算吞吐量（>1000客户/分钟）
   - 缓存策略（Customer 表缓存 LTV 结果）
