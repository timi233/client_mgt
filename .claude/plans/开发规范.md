# B2B CRM 项目开发规范

**最后更新**: 2026-01-26
**适用范围**: B2B CRM 项目后端开发 (Django/DRF)

本文档旨在统一项目开发标准，提升代码质量、安全性和可维护性。针对技术方案 Review 中发现的 P2 级问题（数据验证、迁移策略、SQL 安全），本文档提供了明确的约束和实施指南。

---

## 1. 代码规范 (Code Style)

遵循 PEP 8 标准和 Django 官方最佳实践。

-   **格式化**: 使用 `black` 进行代码格式化。
-   **导入排序**: 使用 `isort` 管理导入顺序。
-   **命名**:
    -   类名: `CapWords` (如 `CustomerProfile`)
    -   函数/变量: `snake_case` (如 `calculate_ltv`)
    -   常量: `UPPER_CASE` (如 `MAX_RETRY_COUNT`)

---

## 2. 数据验证规范 (Data Validation)

**核心原则**: 永远不要信任用户输入。数据完整性校验必须在 Model 层和 Serializer 层双重保障。

### 2.1 Model 层验证 (针对 Issue 11)
必须在 Model 的 `clean()` 方法中实现跨字段的业务逻辑验证，确保数据库落库数据的绝对一致性。

#### ✅ 正确示例
```python
from django.core.exceptions import ValidationError

class Quote(models.Model):
    subtotal = models.DecimalField(...)
    discount_value = models.DecimalField(...)
    total_amount = models.DecimalField(...)
    
    def clean(self):
        # 1. 验证必填项和范围
        if self.discount_value < 0 or self.discount_value > 100:
            raise ValidationError({'discount_value': '折扣必须在 0-100 之间'})

        # 2. 验证金额计算一致性 (Issue 11 修复)
        calculated_total = self.subtotal * (1 - self.discount_value / 100)
        # 使用 epsilon 处理浮点数/Decimal 精度差异
        if abs(self.total_amount - calculated_total) > 0.01:
            raise ValidationError({
                'total_amount': f'金额计算不一致。预期: {calculated_total}, 实际: {self.total_amount}'
            })

    def save(self, *args, **kwargs):
        # 3. 保存前强制验证
        self.full_clean()
        super().save(*args, **kwargs)
```

#### ❌ 错误示例
```python
def save(self, *args, **kwargs):
    # 错误：只在 save 中做简单的赋值，没有验证逻辑
    # 如果外部直接调用 save() 而不经过 serializer，会产生脏数据
    self.total_amount = self.subtotal - self.discount
    super().save(*args, **kwargs)
```

### 2.2 Serializer 验证
DRF Serializer 处理前端输入格式校验，Model 处理核心业务逻辑校验。

## 3. 数据库规范 (Database Standards)

### 3.1 Migration 规范 (针对 Issue 12)
针对多租户架构，Schema 变更极其敏感。

-   **禁止自动生成的空操作**: 每个 Migration 文件必须有明确意图。
-   **数据迁移**: 涉及 `tenant_id` 或数据结构变更时，必须编写数据迁移脚本。
-   **回滚支持**: 必须实现 `RunPython` 的 `reverse_code`。

#### ✅ 正确示例
```python
from django.db import migrations

def set_default_tenant(apps, schema_editor):
    # 使用 apps.get_model 获取历史版本模型，而非直接 import
    Customer = apps.get_model('crm', 'Customer')
    DefaultAccount = apps.get_model('crm', 'Account')
    
    default_account = DefaultAccount.objects.first()
    if default_account:
        # 批量更新，性能更好
        Customer.objects.filter(tenant_id__isnull=True).update(tenant_id=default_account.id)

def reverse_func(apps, schema_editor):
    # 提供回滚逻辑
    pass

class Migration(migrations.Migration):
    dependencies = [('crm', '0001_initial')]

    operations = [
        # Issue 12: 包含明确的数据迁移逻辑
        migrations.RunPython(set_default_tenant, reverse_func),
    ]
```

#### 📝 说明
-   **备份**: 生产环境执行 Migration 前，DevOps 必须进行数据库快照。
-   **注释**: Migration 文件顶部需添加注释说明变更目的。

### 3.2 SQL 安全规范 (针对 Issue 20)
**严禁 SQL 注入**。在 Django 中，只要正确使用 ORM，99% 的注入风险都可避免。

#### ✅ 正确示例 (ORM)
```python
# 推荐：使用 ORM 查询
customers = Customer.objects.filter(name__icontains=user_input)

# 允许：必须使用参数化查询的 raw SQL
sql = "SELECT * FROM crm_customer WHERE name = %s"
Customer.objects.raw(sql, [user_input])

# 允许：使用 cursor 参数化执行
with connection.cursor() as cursor:
    cursor.execute("UPDATE crm_customer SET status = %s WHERE id = %s", ['active', customer_id])
```

#### ❌ 错误示例 (禁止)
```python
# 危险：直接字符串拼接，极大注入风险
query = f"SELECT * FROM crm_customer WHERE name = '{user_input}'"  # 禁止！
Customer.objects.raw(query)

# 危险：.extra() 方法已废弃且易受攻击，禁止使用
Customer.objects.extra(where=[f"name = '{user_input}'"])  # 禁止！
```

## 4. 安全规范 (Security)

### 4.1 通用防护
-   **CSRF**: 所有 POST/PUT/DELETE 请求必须携带 CSRF Token（API 使用 Bearer Token 认证除外）。
-   **XSS**: 模板渲染默认开启自动转义；富文本输出必须使用 `bleach` 清理。
-   **敏感信息**: 密码、密钥禁止明文存储；日志中禁止打印 PII（个人身份信息）和 Token。

### 4.2 权限控制
-   **水平越权 (IDOR)**: 必须使用 `TenantAwareModel` 或 `TenantManager` 确保无法访问其他租户数据。
-   **垂直越权**: 关键操作（如删除、导出）必须检查 `request.user.has_perm()`。

## 5. 测试规范 (Testing)

-   **覆盖率**: 核心业务逻辑（Model 方法、Service 类）单元测试覆盖率需 > 90%。
-   **测试隔离**: 每个测试用例必须独立，使用 `TransactionTestCase` 或 `TestCase` 自动回滚数据。
-   **Mock**: 外部依赖（飞书 API、S3、Celery）必须 Mock，禁止在测试中发起真实网络请求。

## 6. Code Review 检查清单

提交代码前，请自检以下项目：

### 安全性
- [ ] 是否存在 SQL 拼接？(使用 ORM 或参数化查询) (Issue 20)
- [ ] 是否在 Model.clean() 中验证了关键数据的完整性？(Issue 11)
- [ ] 是否处理了租户隔离？(filter 中包含 tenant_id 或使用 Manager)
- [ ] 权限检查是否覆盖了所有 API 端点？

### 数据库
- [ ] Migration 文件是否包含数据迁移逻辑？(如涉及结构变更) (Issue 12)
- [ ] 是否有可回滚方案？
- [ ] 索引是否已添加？(针对高频查询字段)

### 代码质量
- [ ] 变量命名是否清晰？
- [ ] 复杂逻辑是否有注释？
